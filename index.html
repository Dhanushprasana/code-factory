QUALITY GOVERNANCE
Source of truth
AI can propose the answer key. It cannot certify itself as correct.
Independent review required

  
Recommended policy: treat generated task requirements as a draft specification. Establish expected behavior from product-owner-approved examples, domain rules, repository contracts, and independent reviewer decisions. Freeze that specification before generating solutions and tests.

  
Evidence hierarchy
Resolve disagreements from the top down
  1. Approved product requirementHuman owner accepts scope, rules, edge cases, and explicit non-goals.
  2. Independent examples / domain oracleExpected inputs/outputs reviewed separately from the solution-writing model.
  3. Existing repository contractsPublic API behavior, schemas, invariants, and regression tests at the pinned commit.
  4. Reference solution and generated testsCandidate evidence only; never the sole authority for expected behavior.
Require at least one reviewer to approve the spec and boundary examples before reference implementation work begins. Record disagreements and decisions.

    
MFA test strategy
No real user codes
For MFA tasks, do not ask an AI agent for a code from a real authenticator or production account.
Preferred:  use an auth-provider sandbox or test tenant with documented test OTPs.
TOTP:  seed a disposable test account with a test-only secret and compute time-based codes in the test harness using a controlled clock.
SMS/email OTP:  route to a fake provider or local inbox capture; assert the delivered message and use its code in the test.
Isolation:  store test secrets in CI secret storage, never in the prompt, screenshot, logs, or exported task.
Security:  production credentials, real phone numbers, and real MFA bypasses are out of scope.
Verify success, invalid/expired/replayed code, rate limits, recovery path, and that MFA cannot be skipped.

  

  
Versioning recommendation
Immutable benchmark releases
Task packageSemantic version for approved instructions + acceptance criteria, e.g. v1.3.0. Any behavior/spec change creates a new version.
Test suiteIndependent immutable version/hash. If tests change, issue a new benchmark version and rerun every compared agent.
Repository baselinePin full Git commit SHA and dependency/environment image digest, not a branch name alone.
Agent attemptRecord agent/model/adapter version, config, task version, base SHA, patch checksum, and logs per attempt.
A UI code change should not silently rewrite tests for one model. Update the product/task spec and test suite as a new version, validate it independently, then rerun all models on that same version for a fair comparison.






  
TASK RELEASE
Publish task
Freeze an approved benchmark version and make its package available for agent runs.
Draft · not published

  
Release details
Immutable after publish
Recommended version rule: major = incompatible task/spec changes; minor = new acceptance behavior; patch = typo/metadata fixes that do not alter expected behavior. Any test behavior change requires a new immutable suite hash and rerunning every agent.

    
Release checklist
Required gates
Publish is blocked until every required gate is checked. Demo publish only changes the local UI state.
